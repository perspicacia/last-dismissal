# 로컬 웹 미리보기 실행·복구

2026-10-07 사용자 요청: 수정 후 반복되는 웹 미리보기 접근 실패를 진단하고 안정적인 실행·상태 확인·복구 방법을 제공한다. [Issue #119](https://github.com/perspicacia/last-dismissal/issues/119). 캐릭터 외형은 변경하지 않는다.

- 플레이 주소는 `http://127.0.0.1:8080/` 하나로 유지한다. 실행 폴더와 무관하게 이 프로젝트 루트를 제공하며 포트 충돌을 피하려고 다른 포트로 자동 이동하지 않는다.
- `npm start`는 서버 상태를 확인하고, 프로젝트 서버가 정상이라면 재사용한다. 서버가 없으면 프로젝트 내 로그/상태 파일을 사용하는 독립 프로세스로 실행한다. 실행한 터미널/작업이 끝나도 유지하되 재부팅 후 자동 실행을 위한 OS 설정은 추가하지 않는다.
- `npm run preview`는 서버 준비/문서 루트를 확인한 뒤 Mac의 Chrome으로 위 주소를 연다. Chrome 실행 명령 성공, 실제 브라우저 렌더링, 앱 파일 오류 해결을 구분한다.
- 상태 확인은 실제 HTTP 응답과 프로젝트 파일/문서 루트를 검증한다. 다른 서버가 8080을 점유하면 정확히 알리고 유지한다. 종료·재시작 명령은 검증된 자체 서버만 대상으로 하며 오래된 PID로 다른 프로세스를 종료하지 않는다.
- 관리 서버는 파일을 요청 때 읽고 개발 파일의 캐시를 막아 코드 수정 뒤 새로고침에 새 내용을 제공한다. 로컬127.0.0.1에만 바인딩한다.
- 앱의 ‘이 클라우드 파일을 불러오지 못했습니다’ 메시지는 프로젝트 코드에 없으며, 로컬 서버의 성공만으로 앱 오류의 원인/해결을 확정하지 않는다. 앱 파일 로딩 문제는 직접 Chrome 실행 경로와 별도로 보고한다.
- 기존 PNG/GLB, 게임 판정/카메라/음향, 사용자 열린 탭과 다른 작업을 보존한다. 패키지 설치, 배포, 로그인 항목/LaunchAgent, 네트워크·보안 설정 변경은 하지 않는다.

## 완료 조건

- 서버 없음→시작, 반복 시작→같은 프로세스 재사용, 실행 명령 종료 후 유지, 상태 확인, 자체 서버 재시작, 파일 수정 후 HTTP 새 내용, 올바른 루트/포트 충돌·오래된 PID 보호를 검증한다.
- 별도 테스트 루트의 수정/복구를 사용해 실제 게임 파일을 검증 목적으로 덮어쓰지 않는다. 브라우저 새로고침/재열기와 정적 모듈 로딩을 가능한 경로로 확인한다.
- 자동 검사와 사용자 Mac Chrome의 실제 픽셀 확인, 미검증 GUI/앱 오류를 구분해 기록한다.
- 진행 기록·실행 문서를 갱신하고 커밋/Push/검토 PR로 제출한다. main 병합과 배포는 진행하지 않는다.
