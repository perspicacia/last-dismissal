# 게임 재점검과 얼굴 없는 학생 (Issue #70)

2026-10-04: 아래 이미지 평면 구현은 초기 기록이다. 현재 Three.js의 닫힌 3D 메시·원본 사진 투영은 [교실 입체감 명세](classroom-character-depth.md)가 우선한다. 기존 자산/배치/로딩·충돌/비공격 규칙과 Canvas 사진 투영은 유지한다.

사용자는 재점검·문제 수정·새 캐릭터 하나의 디자인/배치를 위임했다. 기존 캐릭터 추가 이미지 제작 중단은 유지하며 새 학생만 제작한다.

## 새 캐릭터

- 낡은 회색 교복 재킷과 긴 바지, 짧고 흐트러진 검은 머리, 매끈하게 눈·코·입이 없는 도자기 얼굴. 옷감/피부 재질은 기존 실사풍 인형들과 맞춘다. 피나 상처·기존 영화 인물 복제는 없다.
- 전신 정면의 신규 투명 PNG 한 개를 image_gen으로 제작하고 원본·프롬프트/생성 정보를 보존한다.
- 3-3 교실 안쪽 칠판 옆 오른쪽 구석 `(3.55, 9.35)`에 높이 약 1.7m로 서 있다. 책상과 벽을 뚫지 않고 발이 바닥에 닿으며 중앙 탐색/문 복귀 동선을 막지 않는다. 얼굴은 교실 중앙을 향한 고정 방향이다.
- Three.js의 고정 이미지 평면과 Canvas의 원근 사각형은 같은 원본 비율·높이·위치를 사용한다. 이미지 준비 전/실패 시 숨기며 판정/이동은 계속한다. 재입장/재시작은 중복 생성하지 않는다.
- 새 학생은 정적인 분위기 요소로 공격·패배·표정/음향을 추가하지 않는다. 토끼가 유일한 공격자다. 기존 학생 인형·창밖 귀신·음악실 남자아이 외형은 보존한다.
- 첫 화면의 배경 쪽에 새 학생을 포함하며 기존 네 얼굴·제목·시작 버튼을 가리지 않게 한다.

## 점검·수정

- 다섯 방의 실제 입장/복귀·소품 충돌·기존 공포 요소, 토끼 발견·게임 오버·재시작·Escape, 음소거와 비활성 화면 상태를 확인한다.
- 재현되는 오류는 재현 절차·기대 결과·실제 결과·수정 후 검증을 기록한다. 발견한 상태/이동 문제는 의미 있는 회귀 테스트로 확인한다.
- 첫 화면에서 음소거를 껐다 켜도 시작 전 BGM은 재생하지 않는다. 오디오 재개가 늦게 완료돼도 Escape 후 음악이 되살아나지 않으며 새 게임의 오디오를 중단하지 않는다.
- WebGL 실패 안내는 제목/시작 버튼 아래에서 표시하고 첫 화면을 가로로 밀지 않는다. 검증 화면은 현재 index.html을 캐시 없이 읽어 실제 최신 UI를 확인한다.
- `npm test`, `git diff --check`와 실제 브라우저 검증을 구분한다. Three.js/Canvas 호환·이미지 실패 시 시작/복귀를 확인하고 검증용 설정은 일반 UI에 노출하지 않는다.
- 실제 모바일 기기/청감·사용자 체감 공포 강도와 이미지 평면의 측면 한계는 미확인 사항에 기록한다.
