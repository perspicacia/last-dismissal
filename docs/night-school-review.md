# 야간 학교 재점검 — 2026-10-03, Issue #70

범위는 [얼굴 없는 학생과 재점검 명세](../specs/faceless-student-upgrade.md)다. Codex 웹 미리보기에서 실제 컨트롤러를 키보드/화면 버튼으로 조작했다. 토끼 위치만 무용실로 고정하는 `tests/fixtures/three-flow.html?safe&silent`를 사용해 재현성을 확보했다. 일반 게임에는 위치 고정이나 음향 출력 차단이 없다.

## 자동 검증

`npm test` 140개 통과. 신규 검증은 학생 PNG 비율·발 접촉·벽 안쪽 배치, 몸 관통 방지·기존 책상/의자 충돌·중앙 통로, 비공격 판정, Canvas 원근·준비 전/실패 처리, Three.js 중복 생성 방지·재로딩 복구, 오디오 비동기 수명주기다. `git diff --check`도 통과했다.

## 실제 플레이 확인

- Three.js: 시작 → 3-1 → 3-2 → 3-3 → 음악실 → 무용실 순으로 각 입장·복도 복귀를 확인했다. 방문 기록은 5/5까지 진행됐고 무용실 토끼 발견 → 게임 오버 → 재시작(방문 빈 값·토끼 숨김) → Escape 첫 화면이 정상이다.
- 3-1 책상 인형, 3-2 바닥 인형의 기존 외형과 음악실 의자의 남자아이를 확인했다. 3-3 칠판 오른쪽의 새 학생은 발이 바닥에 닿고 얼굴/교복 비율을 유지한다. 몸 앞에서 전진이 막히지만 후퇴·복도 복귀가 가능하며 별도 공격은 없다.
- 비교 화면에서 창밖 공, 근접한 긴 머리 귀신의 미소, 코너의 웅크린 그림자를 확인했다. 새 학생 외 다른 캐릭터 이미지는 변경하지 않았다.
- Canvas: 새 학생의 원근/발 접촉, 3-3 입장·복귀, 무용실 토끼 → 게임 오버 → 재시작 → Escape를 확인했다. Canvas 전체 다섯 방의 외형을 다시 검증한 것은 아니다.
- 새 학생 이미지 실패 강제 화면: `unavailable` 상태에서도 시작·3-3 입장·복귀·Escape가 가능하다. 일반 게임에는 실패 강제 설정이 없다.
- 일반 게임: 음소거 상태의 키보드 Enter 시작·Escape 복귀, Three.js 준비/학생 이미지 `ready`, 오류·경고 없음. 첫 화면은 1280×720, 390×844, 320×667, 844×390에서 다섯 얼굴·제목·시작 버튼과 가로 넘침 없음을 확인했다. 임시 화면 크기는 해제했다.
- 관련 주 게임·이미지 실패·비교 화면의 예상하지 못한 콘솔 오류/경고는 없다. Canvas 강제 WebGL 초기화 실패/전환 로그는 예상 결과다.

## 미확인·표현 한계

소리 출력 없이 오디오 상태/분석기·호출 흐름을 검증했으므로 실제 청감은 확인하지 않았다. 실제 모바일 기기/GPU 성능과 Chrome 별도 전체 플레이도 미확인이다. 원본 학생 인형은 2.5D이고 새 학생/창밖 귀신/남자아이는 이미지 평면이라 낮은 측면·후면에서 얇거나 납작해 보일 수 있다. 기존 인형과 닮은 완전한 관절형 3D 모델은 이번에 제작하지 않았다. 리뷰·main 병합·배포는 진행하지 않았다.
