# 학교 3D 보완 검증

2026-10-06, [명세](../specs/3d-quality-upgrade.md), [Issue #117](https://github.com/perspicacia/last-dismissal/issues/117), [검토 PR #118](https://github.com/perspicacia/last-dismissal/pull/118). 일반 게임에 재질/그림자/충돌/가구 렌더/텍스처 수명 관리·첫 화면 셰이더 준비를 적용했다. 리깅 캐릭터는 원본 우선 규칙에 따라 별도 검토 후보로 준비했다.

## 적용 내용

1. 목재·벽·금속에 결정적인 색/노멀/거칠기 맵과 공유 캐시를 추가했다. 습기 얼룩은 색 오버레이로 유지한다. 국소 천장등 한 개씩 1024 그림자 맵을 사용하고 기존 복도 소등 신호를 따른다. 방향광 범위를 좁히고 2048→1024로 줄였다. 반사는 작은 절차적 PMREM 조명 근사이며 움직이는 장면의 실시간 반사가 아니다.
2. 복도 책상 렌더·플레이어/고양이 장애물 치수를 공유한다. 정면·옆걸음·대각선 관통을 막고 가장자리를 따라 이동한다. 반복 교실 책상·의자는 기존 치수/회전을 가진 인스턴스로 그린다. 표정 텍스처는 재사용하고 재시작의 이전 시계 캔버스 맵은 해제한다.
3. [새 모델 자산 기록](../assets/models/student-reference-rig.md)에 실제 골격/웨이트·두 검토용 동작과 전체 GLB 로딩 경로를 마련했다. 기존 PNG·기존 모델·일반 인형 외형은 유지했다. 모든 귀신의 완성된 전 방향 모델을 제작한 것은 아니다.
4. 첫 화면 비활성 시간에 복도와 다섯 방의 셰이더를 `compileAsync`로 순차 준비한다. 플레이/일시정지/캡처/숨김 탭에서는 다음 작업을 시작하지 않는다. 시작은 준비 완료를 기다리지 않으며 장면을 그리거나 게임 판정을 진행하지 않는다. 늦게 도착하는 이미지/음악실 몸통은 큐를 갱신하고 준비 실패는 일반 렌더로 대체한다. 토끼 기본 맵을 등장 전에 연결하되 복도에서 표시하지 않는다.

## 자동 검증

- 전체 `npm test`: **240/240 통과**. 추가한 16개는 결정적 맵/색 공간/유효 법선·정면/옆걸음/대각선 충돌·가구 치수/기울기·실내 그림자/소등·30번 시계 교체/표정 텍스처 재사용·성능 계산·실제 GLB 웨이트/본/클립/원본 픽셀·독립 인스턴스/실패 재시도를 확인한다. 후속 6개는 준비 큐의 단일 실행/중복 합치기·플레이 중 중단/복귀·진행 중 자산 변경·실패/미지원/해제와 토끼 맵 준비의 비등장을 확인한다.
- Node에서는 실제 GLB의 스킨/애니메이션을 production GLTFLoader로 읽고 이미지 없이 검증한다. 브라우저에서 내장 PNG 디코딩과 외형을 추가로 확인한다.
- 기존 tracked PNG/GLB **19개**의 HEAD 대비 바이트 보존 확인. 새 모델은 같은 생성 명령의 SHA-256 재현 확인. JS/fixture 구문·상대 링크·`git diff --check` 확인.

## 실제 브라우저 확인

사용자 **Mac의 Codex 내장 브라우저(IAB)**, 기존 127.0.0.1:8080 서버를 재사용했다. 사용자 Chrome 탭·문서·미저장 작업은 조작하지 않았다. 검증 탭은 배경에서 별도로 사용했다.

- `quality-review.html`: 복도·책상/바닥·3-1·음악실 재질과 조명, 표면 맵 비교·소등/복구를 확인했다. 일반 Three.js 콘솔 오류/경고 없음.
- 실제 컨트롤러 `three-flow.html?safe&silent&activeClock&quality`: 시작→책상 앞에서 실제 W 입력→3-1 토끼 근접 이빨/비공격(비명 0)→P 캡처/장면 고정→Esc 설정/위치 보존→재개/복귀→3-2/3-3/음악실/무용실(방문 5/5)→공격 표정/비명 1→GAME OVER→다시 하기(방문 0/5, 공격자/토끼 숨김·기본 표정)를 확인했다. W 입력의 책상 앞 정지 위치는 x=2, z≈2.623 (책상 시작 z=2.85, 플레이어 반경 0.22)다.
- 정상 컨트롤러의 추가 종료/재시작 **3회** 모두 텍스처 **73개**, geometry **1,835개**로 같았다. 최초 장면/고양이의 GPU 업로드는 초기 개수 증가에 포함하며 개수를 메모리 바이트로 해석하지 않는다. 콘솔 오류/경고 없음.
- Canvas 강제 호환 `?safe&silent&activeClock&quality&compat`: 책상 앞 x=2,z=2.625 정지, 3-1 토끼 이빨/비공격→무용실 발견/GAME OVER→재시작 방문 초기화 확인. `rendererReady=canvas`; 의도한 WebGL 생성 실패와 Canvas 전환 로그 2건 외 오류/경고 없음.
- 밝은 모델 비교: 정면/사선/측면/뒤/얼굴·누운 자세와 두 관절 동작/학교 조명을 확인했다. 17 본·36 런타임 스킨·2 클립과 실제 bone 회전 값을 확인했다. 일반 게임에는 새 모델을 적용하지 않았다.
- 누운 후보의 단순 전체 회전에서 몸/발 부유를 발견해 검토 자세의 골반/목·고관절을 조절했다. 머리/치마/두 신발은 바닥 관통 없이 지지 높이 5cm 안에 있음을 자동 검증하고 실제 화면을 다시 확인했다. 정면 복귀/반복 자세 선택은 본을 초기화한다. 일반 `/`도 음소거 시작→Esc→처음 화면 복귀를 확인했고 오류/경고 없음.
- 실제 확인에서 예전 모듈 URL이 남아 책상 충돌이 갱신되지 않은 상황을 발견했다. 일반 entry와 변경된 의존 모듈의 cache key를 갱신한 뒤 Three.js/Canvas 두 경로에서 재확인했다. 외형 후보도 새 GLB의 cache key를 분리했다.

개발용 `safe`는 공격자 방을 마지막 무용실로 고정하고 `silent`는 장치 소리 출력을 차단한다. `activeClock`은 검증 탭의 포커스/숨김 시계만 우회하며 `quality` 위치 버튼으로 경로를 단축한다. 방 입장/발견/종료 타이머/재시작/입력은 실제 컨트롤러다. 일반 게임에는 이 조건이 없다. 따라서 이 확인을 전체 길을 수동 보행한 플레이나 실제 음향 청감으로 보고하지 않는다.

## 동일 장면 측정

IAB 검증 탭 하나, 1280×720 viewport, 1.5 DPR, canvas 1920×862, 3-1 비교 위치 (0,4.2), 정상 광원, 준비 비용이 지난 마지막 **120 frames**. 같은 재질/조명과 가구 배치에서 개별 렌더/인스턴싱만 비교했다.

| 항목 | 개별 가구 | 인스턴싱 |
| --- | ---: | ---: |
| 프레임당 렌더 호출 (그림자 포함) | 973 | 529 |
| 렌더 triangles | 226,698 | 245,110 |
| geometry 개수 | 837 | 613 |
| texture 개수 | 36 | 36 |
| CPU 제출 중앙값 | 2.50 ms | 2.10 ms |
| CPU 제출 p95 | 3.30 ms | 4.10 ms |
| 중앙 프레임 간격 / 환산 FPS | 16.70 ms / 59.9 | 16.70 ms / 59.9 |

호출 **45.6% 감소**, geometry 개수 **26.8% 감소**. 묶음 단위 culling 때문에 triangles는 **8.1% 증가**했다. 두 방식이 이 조건에서 약 60 FPS이므로 FPS 향상을 보장하지 않는다. CPU는 draw/update/제출 시간이며 GPU 실행 시간을 측정하지 않았다. 여러 검증 탭을 동시에 렌더하면 간격이 늘어 별도 단일 탭으로 다시 비교했다. 새 장면 첫 쉐이더 준비에서 1초 이상 제출 표본이 관찰됐으며 정상 상태 측정에서는 제외했다.

## 첫 화면 셰이더 준비 후속 확인

`shader-warmup-review.html`은 실제 `Corridor`/`ThreeSchoolView`를 사용한다. 첫 화면에서 준비 완료를 기다린 뒤 같은 3-1 위치 (0,4.2)를 처음 그렸다. 사용자 Mac IAB 검증 탭 하나, 1280×720 viewport/DPR 1.5, 같은 재질·광원·가구, 원본 캐릭터로 비교했다. 두 방식의 호출 529/triangles 245,110은 같다.

| 사전 준비 | 첫 CPU 제출 | 첫 교실 렌더 후 프로그램 수 |
| --- | ---: | ---: |
| 꺼짐 | 193.80ms | 17 (해당 방만) |
| 켜짐, 여섯 장면 완료 | 174.50ms | 46 (모든 방 포함) |

준비 완료 직전에는 프로그램 40개였고 첫 렌더가 깊이/그림자 프로그램 6개를 추가했다. 준비 꺼짐의 앞선 측정은 413.20ms였다. 새 WebGL 컨텍스트로 비교했지만 브라우저/드라이버의 시스템 캐시를 비운 측정은 아니며 단일 표본 편차가 크다. 이 결과로 고정된 개선율이나 첫 프레임 지연 해소를 주장하지 않는다. `compileAsync`는 셰이더 준비 비용 일부를 첫 화면으로 옮기며 텍스처/geometry 업로드와 그림자 깊이 패스는 첫 렌더에 남는다. 준비 프로그램을 모든 방에 대해 보관하는 비용도 있다. GPU 시간과 모바일은 미측정이다.

일반 `/`와 실제 컨트롤러에서 여섯 장면 준비를 확인했다. 후속 실제 흐름은 음소거 시작→3-1 토끼 이빨/비공격→P/캡처→Esc/재개→다섯 방 안쪽 방문 5/5→공격 표정/GAME OVER→재시작 방문 0/5·공격자/토끼 숨김→Esc/첫 화면 복귀다. 재시작은 준비 목록을 유지한다. Three.js 오류/경고 없음. Canvas 강제 호환의 GAME OVER/재시작도 정상이며 의도한 초기화 실패와 전환 로그 2건만 발생했다. 검증용 위치 버튼/고정 마지막 방/백그라운드 시계/장치 무음 출력은 일반 게임에 적용하지 않는다.

## 남은 작업

- 사용자 외형 채택: 원본 기준 인형 후보의 얼굴/목·머리 컬/옷/팔다리 비율과 양옆/뒤·누운 모습. 한 장 사진 기반의 근사이며 일반 게임에서 원본과 닮은지 승인된 모델로 확정되지 않았다.
- 전 방향 캐릭터 조형/전용 UV·머리카락/옷 질감·표정 모프·걷기/공격 클립과 다른 귀신 전환은 후속 범위다. 측면/후면 기준을 먼저 정해야 한다.
- 셰이더 사전 준비는 추가했으나 시스템 캐시가 완전히 없는 첫 입장·텍스처 업로드/깊이 패스 준비·모바일/저사양 GPU/실제 Chrome·실제 음향 청감은 미확인이다. 동적 실내 AO·실시간 반사·LOD/장면별 지연 로딩은 추가하지 않았다.
- 다음 작은 작업: 밝은 원본 비교 후보를 검토해 수정할 외형/채택 범위를 확정한 뒤 한 인형의 일반 게임 연결을 진행한다. 리뷰/main 병합/통합 검증은 이후, 배포는 요청 시 진행한다.
