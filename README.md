# 마지막 하교

학교를 배경으로 한 생존 공포게임. 목표는 짧은 플레이로 규칙과 분위기를 전달하는 것이다.

## 실행

프로젝트 폴더에서 `npm start` 또는 `python3 -m http.server 8080 --bind 127.0.0.1`을 실행하고 브라우저에서 http://127.0.0.1:8080 을 연다. 브라우저 실행에는 저장소의 `vendor/` 모듈을 사용하므로 CDN 연결이나 패키지 설치가 필요 없다. 의존성을 재설치할 때는 `npm ci`를 실행한다. HTML 파일을 직접 열면 ES 모듈 제한 때문에 실행되지 않을 수 있으므로 로컬 서버를 사용한다.

- 일반 플레이: 토끼의 접근을 확인하며 60초 생존한다. 10초 관찰→6초 접근 경고→공격→4초 퇴각이 반복된다.
- ↑↓/WS 이동, ←→/AD 회전. 가까운 교실 문에서 E/교실 들어가기. 교실 안에서는 E/문 닫기로 방어한다.
- 문은 7초 후 자동으로 열리고 3초 동안 다시 닫을 수 없다. 직접 열어도 회복 시간이 적용된다. 닫힌 동안 복도로 나갈 수 없다.
- 공격 순간 교실의 문이 닫혀 있으면 살아남는다. 실패하면 토끼가 눈앞에 나타난 뒤 게임 오버. 60초 생존하면 탈출한다.
- 승리·패배 화면에서 재시작. Escape는 처음 화면이다. 화면에 키 안내·시연 버튼은 추가하지 않았다.
- 소리 없이도 접근 경고·토끼 위치와 표정을 확인할 수 있다. M 음소거. 숨긴 탭/포커스를 잃은 창에서는 시간을 멈춘다.
- `npm test`: 생존·문 타이밍·패배·초기화와 기존 이동·렌더 회귀 테스트. 현재 완료 조건은 [specs/rabbit-survival.md](specs/rabbit-survival.md)다.

## 파일 구성

`index.html`은 화면, `style.css`는 화면 스타일, `survival.js`는 생존·공격·문 시간 판정, `logic.js`는 이전 관찰 버전 판정, `game.js`는 생존 게임 화면 상태, `audio.js`는 합성 음향, `movement.js`는 이동·충돌·조사 거리, `window-view.js`는 창밖 숲·가로등·귀신 풍경, `corridor.js`는 이동·렌더 연결을 담당한다. 기본 게임은 `three-school.js`의 Three.js 실내 렌더와 `three-outdoors.js`의 실제 3D 외부 풍경을 사용한다. 기존 Canvas 렌더는 비교 화면 및 WebGL 초기화 실패 시 호환 화면으로 유지한다. 생존 규칙을 늘릴 때는 `survival.js`의 상태 전환, `game.js`의 조작·화면, `corridor.js`와 `three-school.js`의 연출을 함께 확인한다.

## 현재 첫 생존 버전

토끼 한 캐릭터의 접근 징조와 문 방어를 먼저 구현했다. 학생 인형은 교실의 정적인 장식이며 창밖 귀신의 공격은 후속 기능이다. 이번 버전은 고정 주기로 접근한다. 기존 계단 정답 선택 게임 모듈은 이전 버전 회귀용으로 보존한다.

## 음향 기획

큰 소리로 놀라게 하기보다, 익숙한 공간이 낯설어지는 분위기를 만든다.

1. 시작 화면: 무음. 사용자가 시작 버튼을 누른 뒤에만 오디오를 켠다.
2. 복도: 낮은 드론과 형광등 소리. 드론은 작게 유지하고 장시간 들어도 부담이 적도록 한다.
3. 토끼 경고: 짧고 낮은 불협화음. 위치·표정·문구로 같은 위험을 전달한다.
4. 문 방어 성공: 작은 종소리. 잡히면 기존 낮은 경고음을 재생한다.
5. 탈출: 긴장음을 낮추고 새벽 분위기의 화음을 낸다.

초기 버전은 Web Audio로 직접 합성한 음향을 사용한다. 외부 음악 파일이나 다운로드가 필요하지 않다. 이후 실제 음원으로 교체할 때 출처와 이용 조건을 기록한다. 음소거와 음량 조절을 제공하고, 소리가 없어도 판정 가능하도록 설계한다.

노트북 스피커에서도 들리도록 196~349Hz의 드론과 24초 반복 선율을 함께 사용한다. 기본 음량은 50%다. 상단의 ‘소리 확인’은 오디오를 다시 시작하고 확인용 종소리를 재생한다. 시작 전에는 음악이 재생되지 않으며, ‘소리 확인’을 누르면 시작 화면에서도 들을 수 있다. ‘BGM 재생 중’은 브라우저의 오디오 실행 상태를 뜻하며, 기기나 브라우저 자체의 음소거 여부까지 확인하지는 않는다.

## 범위와 이후 개선

현재 버전은 화살표로 걷고 둘러보는 1인칭 복도 탐색 게임이다. 벽을 통과하지 못하며 가까이에서 바라보는 사물만 조사할 수 있다. Three.js로 학교 실내와 창밖 공간을 표현한다. 창밖 나무·가로등·운동장은 실제 거리별로 배치하며 조명과 그림자를 사용한다. 불규칙한 접근 AI와 추가 맵은 후속 범위다. 후속 개선에서는 플레이어가 접근 경고를 알아보고 문을 닫을 시간적 여유가 있는지 확인한다.

## 토끼의 두 얼굴

정상 토끼는 입을 닫은 모습이다. 접근 경고 동안 토끼가 복도 앞으로 이동하고 날카로운 이빨을 드러낸다. 방어 후 퇴각하면 기본 표정으로 돌아온다. 두 장의 투명 PNG를 교체하는 연출이며, 턱이 연속적으로 움직이는 3D 애니메이션은 아니다.

창밖 정상 풍경은 숲과 가로등이다. 이전 창문 이상현상 비교 화면에서는 검은 머리의 도자기 귀신이 앞쪽 창 밖에 나타난다. 현재 생존 플레이의 공격자는 토끼 하나다. 개발용 렌더 비교는 서버 실행 후 `http://127.0.0.1:8080/tests/fixtures/window-review.html`에서 확인한다. 플레이 화면에 시연 버튼은 추가하지 않았다.

시계·창틀·문틀·게시판·형광등의 깊이는 `clock.js`와 `scene-depth.js`에서 세계 좌표로 투영한다. 창밖 숲은 거리별 시차를 사용한다. 시계 정상/이상 및 창틀 비교 화면: `http://127.0.0.1:8080/tests/fixtures/depth-review.html`.

## 3D 화면과 검증

- Three.js 0.186.1 (MIT). `package-lock.json` 버전을 고정하고 배포 모듈·라이선스를 `vendor/`에 보관한다. 라이브러리 갱신 시 `npm ci` 후 `node_modules/three/build/three.module.js`, `three.core.js` 및 LICENSE를 vendor에 동기화한다.
- WebGL2 지원 브라우저가 필요하다. 3D 초기화 실패 시 기존 Canvas 화면으로 전환하며 시작 화면에 호환 화면 안내를 표시한다. 모바일 성능은 별도 확인이 필요하다.
- 토끼와 창밖 귀신은 기존 투명 이미지의 빌보드다. 공간·가구·나무·계단의 3D 전환과 캐릭터 모델링 완료를 구분한다.
- 3D 정상/이상 비교: `http://127.0.0.1:8080/tests/fixtures/three-review.html`. 이 개발용 화면의 버튼은 일반 게임에 표시되지 않는다.
- 실제 생존 UI/컨트롤러 검증: `http://127.0.0.1:8080/tests/fixtures/three-flow.html`. `?compat`를 붙이면 WebGL 실패를 강제해 Canvas 호환을 확인한다.

교실 금발 인형: 현재 생존 플레이에서는 바닥에 누워 있는 장식이다. 이전 이상현상 기립 연출은 개발용 비교 화면에서 보존한다. [상세 조건](specs/classroom-doll.md).

학생 인형의 3D 화면은 `doll-volume.js`에서 이미지 실루엣을 두께와 곡면이 있는 닫힌 메시로 만든다. 관절형 캐릭터 모델은 아니며 Canvas 호환은 기존 이미지 렌더를 유지한다.
